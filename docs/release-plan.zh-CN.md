[English](release-plan.md) | [简体中文](release-plan.zh-CN.md)

状态日期：2026-08-10。仓库当前尚无正式 Release tag。

## 版本序列

| 版本 | 目标时间 | 用户价值 | 必须范围 | 明确不包含 |
| --- | --- | --- | --- | --- |
| `v0.1.0` | 2026-08-16 | 安全的本地优先路由公开预览 | 现有 MVP、字体修复、配置诊断、超时基线、回归测试、安装验证 | 流式输出、fallback、新 provider 协议 |

## 发布授权等级

1. **开发：** 在范围明确的分支实现并测试。
2. **发布准备：** PR、Changelog、版本说明、干净安装测试、产物计划和 CI 证据。
3. **正式发布：** tag、二进制、校验和、包发布和 GitHub Release。每个版本都需要用户明确授权。

PR 合并不自动构成正式发布。

## 发版门槛清单

每次发布必须满足：

- Release commit 上所有适用的 Go 和站点测试通过；
- `go vet`、站点 lint 和生产构建通过；
- macOS/Apple Silicon 上完成干净安装和第一次回答冒烟测试；
- Git 中不包含密钥、本地生成配置或未经评审的二进制；
- README、FAQ、路线图、Changelog 和 Release Notes 中英文同步；
- 记录 CLI、YAML、环境变量和 provider 协议的兼容性影响；
- 如实声明已知限制和上游依赖告警；
- 创建 tag、发布资产或更新安装包前取得明确授权。

## 版本规则

- `0.x.0`：形成完整预览能力或采用里程碑。
- `0.x.y`：预览期缺陷、兼容性、文档或打包修复。
- `1.x.0`：稳定契约后的向后兼容用户能力。
- `1.x.y`：稳定期缺陷、安全、兼容性或打包修复。
- `2.0.0`：CLI、配置、provider 或自动化契约不兼容。

## 回滚与支持

- 保留之前版本的发布产物和校验和。
- 不兼容修改发布前先提供配置迁移说明。
- Release 损坏时停止分发、发布双语通知并推出 patch，不得静默替换已有产物。
- 预览期支持最新 minor 版本；`v1.0.0` 前明确更长期支持窗口。
