# Blossom Router 产品路线图

[English](roadmap.md) | [简体中文](roadmap.zh-CN.md)

状态日期：2026-08-10

## 产品目标

Blossom Router 应在不变成另一个复杂 AI 平台的前提下，减少不必要的高价模型调用。长期承诺是：一个小型入口、明确的 provider 配置、本地优先路由，以及不存在不可见的模型调用。

## 优先级策略

### 必须完成

- 正确性、清晰错误、密钥安全与 loopback UI 安全；
- `auto` 可能选择的每个 route 都有完整配置；
- macOS/Apple Silicon 上的确定性测试与干净安装；
- 面向用户的英文与简体中文文档同步更新。

### 应该完成

- `bloom doctor` 或等价配置诊断；
- 请求超时控制与优雅取消；
- 不改变 provider 选择语义的流式输出；
- 对路由质量、延迟和额度分流进行一周可衡量评估；
- CI、签名发布产物、校验和与简单安装渠道。

### 可以考虑

- chat completions 之外的明确 provider adapter；
- 可选、有界并带可见成本规则的 fallback；
- 用于评估的纯本地使用数据导出；
- Shell completion 和其他打包方式。

### 1.0 前不做

- RAG、MCP、自主 Agent 循环、数据库、账号、托管密钥、远程多用户 UI 或不透明语义路由。

## 成功指标

- 抽样日常工作至少 50% 由 local + cheap route 完成；
- 评估样本中的人工升级率低于 15%；
- 隐藏 provider 调用和凭据泄露均为零；
- route 缺失或不可用时具有可预测的错误行为；
- 准备好的 Mac 从安装到第一次本地回答不超过 15 分钟；
- 英文与中文文档在同一个 PR 中更新。

这些门槛是初始假设。评估前先记录；看到结果后不得修改当期门槛，只能用于下一轮评估。
