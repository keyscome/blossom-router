# 实用性评估指南

[English](evaluation.md) | [简体中文](evaluation.zh-CN.md)

## 什么情况下有实用价值

当你同时使用本地与云端模型、存在大量小型重复提示词，并希望把高价调用变成明确决定时，Blossom Router 很适合。若一个 provider 已能处理全部任务、主要需求是全自动工具型 Agent，或者维护 endpoint 配置花费的时间超过路由节省，它的价值会较低。

## 一周评估方法

选择 30–50 个有代表性的真实任务，每项记录：

| 字段 | 意义 |
| --- | --- |
| 预期任务类型 | 确认样本反映真实工作。 |
| 所选 route | 显示工作负载分布。 |
| 无需升级即可接受 | 衡量路由质量。 |
| 人工升级 | 发现能力分配不足。 |
| 完成时间 | 发现速度过慢的本地模型。 |
| 估算云端成本 | 衡量真实节省，而不只是调用次数。 |

建议的决策信号：

- local + cheap 占比达到 50% 以上，说明额度分流开始有实际意义。
- 人工升级率低于 15%，说明简单路由已经足够准确。
- 某类任务重复失败，说明路由规则或模型匹配存在问题。
- 如果操作路由器花费的时间超过节省的额度，应减少层级并简化配置。

这些只是运营起点，不是普遍结论。请在查看一周结果前先声明自己的阈值。

## 建议上线顺序

1. 配置 `auto` 可能使用的全部 route；初期 cheap 与 normal 可以指向同一 endpoint。
2. 前 10–20 个任务使用 `--dry-run`，比较建议 route 与你的判断。
3. 规则合理后再开始真实调用。
4. 一周后复盘样本；每次只修改一条规则或一个模型。
5. 在自动路由建立可信记录前，strong 任务继续保持明确调用。
